# Разработка кита

## Цикл работы

```bash
npm run dev        # сборка и localhost
# правите tokens/tokens.json или src/*, затем:
npm run build      # пересобрать dist/ и проверить контраст
# обновите страницу (Ctrl+F5)
```

Брендбук читает `dist/`, а не `src/`. Поэтому после правки `tokens/` или `src/` всегда выполняйте сборку.

## Где что менять

| Что | Где | Потом |
|---|---|---|
| Цвет, шрифт, радиус, отступ, размер, движение, тень | `tokens/tokens.json` | `npm run build` |
| Внешний вид компонента | `src/components.css` | `npm run build` |
| Поведение списка, листа, подсказок | `src/select.js`, `src/sheet.js`, `src/tooltip.js` | `npm run build` |
| Страница брендбука | `preview/app.js`, `preview/pages2.js`, `preview/app.css` | обновить страницу |
| Иллюстрации | `assets/illustrations/` | `npm run sync:illustrations` |
| Логотип | `assets/logo/` | не менять без решения владельца |

Не редактируйте файлы в `dist/` вручную: они перезаписываются сборкой (в шапке файла указано `GENERATED`).

## Правила кода

**CSS** (`src/components.css`)

- Только токены `var(--fa-*)`. Hex, готовые px для цветов и длительностей не пишутся (исключения: размеры иконок и разовые геометрические значения вроде ширины ручки листа).
- Градиентов в фонах нет. Маски разрешены.
- `transition: all` запрещён: перечисляйте свойства. Анимируйте `transform` и `opacity`. Короткие переходы цвета допустимы.
- Hover только в `@media (hover: hover) and (pointer: fine)`.
- У каждой анимации есть ветка в `@media (prefers-reduced-motion: reduce)`.
- Для нового компонента сделайте все состояния: обычное, hover, `:focus-visible`, `:active`, disabled, loading, error, success (если применимо).
- Радиусы вложенных элементов считайте по правилу «внешний минус отступ».
- Для новых классов используйте префикс `fa-`, модификаторы через `--`, части через `__`.

**JS** (`src/*.js`)

- Без зависимостей и сборщика, ES5-совместимый IIFE, глобальный объект `FaSomething`.
- Скрипт должен работать без перезагрузки страницы для элементов, добавленных позже.
- Фокус, Esc и клавиатура обязательны для всего, что открывается.

**Брендбук** (`preview/`)

- Страница не должна выходить за границы на 390 и 768 px, в обеих темах, на S, M и L.
- Однотипные карточки в ряду одного размера.
- Тексты только по-русски, в разметке используется обычный дефис `-` (без длинных и средних тире).

## Проверки перед коммитом

1. `npm run build`: сообщение `contrast gate: ... 0 failed`.
2. Просмотрите изменённые разделы брендбука в светлой и тёмной теме, на S, M, L.
3. Раздел «Адаптив» покажет телефон, планшет и ноутбук разом.
4. Поиск по проекту: нет `transition: all`, нет градиентов в фонах, нет длинных и средних тире.
5. Если менялась иллюстрация: `npm run sync:illustrations -- --src ...` без проблем.

Быстрые проверки из терминала:

```bash
# transition: all (допустим только в комментарии в шапке)
grep -rn "transition: *all" src preview
# длинные и средние тире
grep -rnP "[\x{2013}\x{2014}]" src preview docs README.md tokens
```

## Как устроена сборка

`scripts/build.mjs` (Node 18+, без зависимостей):

1. читает `tokens/tokens.json` и раскрывает ссылки `{primitive...}`;
2. считает контраст всех пар (светлая и тёмная темы, острова, переопределения продуктов) и при ошибке завершается с кодом 1, **ничего не записывая**;
3. пишет `dist/css/tokens.css`, `fonts.css`, `components.css` (копия `src/components.css`) и `falcon.css`;
4. копирует `src/tooltip.js`, `select.js`, `sheet.js` в `dist/js/falcon-*.js`;
5. пишет Tailwind v4 `theme.css`, `shadcn-aliases.css`, Flutter (`falcon_theme.dart`, `pubspec_fonts.yaml`), `tokens.flat.json` и `contrast.json`.

Чтобы добавить новый токен: добавьте его в `tokens/tokens.json` (для цвета во все темы), используйте в `src/components.css` как `var(--fa-...)`, выполните сборку и убедитесь, что Tailwind и Flutter получили его.

## Выпуск версии

1. Обновите `CHANGELOG.md` (раздел с версией и датой).
2. Поднимите версию в `package.json`.
3. Выполните `npm run build` и закоммитьте `dist/` вместе с изменениями.
4. Создайте тег: `git tag v0.2.0 && git push --tags`.

Версионирование: изменение токенов, которое ломает имена или значения (например, переименование семантического токена), повышает мажорную версию. Новые компоненты и токены повышают минорную. Исправления вида и документации патч.

## Известные ограничения

- Знак сокола в размерах 16-32 px (иконки приложений, favicon) требует упрощённой версии: в репозитории только исходный логотип.
- Flutter: тема проверена `flutter analyze`, приложение на устройстве не запускалось. Нужны TTF-шрифты (в репозитории woff2).
- Нет React-обёрток, диалогов, графиков, календаря и мобильных паттернов (водитель, диспетчер): они запланированы дальше.
